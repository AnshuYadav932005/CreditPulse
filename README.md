# CreditPulse · Retail Banking Decision Intelligence

CreditPulse covers three connected data-science problems on **real, anonymised bank data**:

| Brief | What FinSight does | Result (honest, out-of-sample) |
|---|---|---|
| **AI-powered alternative credit scoring**: score thin-file customers from behavioural and transactional data; 15% fewer NPAs, faster approvals | LightGBM on 52 point-in-time transaction features, no bureau data. Includes a scorecard scale, SHAP reason codes, and auto-approve / review / decline bands | AUC **0.925** (5×5 CV), **0.969** out-of-time, vs **0.731** for a traditional demographics + loan-terms model. **54% lower NPA rate** at the same 85% approval rate. **70%** of applications decided straight-through |
| **Early warning system for loan delinquency**: flag borrowers 30–60 days ahead with 80%+ precision | Monthly loan-panel model (10.9k loan-months). Label = delinquency onset 30–90 days ahead. Grouped CV by loan. Two alert tiers | **Red tier: 80% precision** (12/15 flagged borrowers went delinquent), median **141 days** of lead time, P25 61 days. Amber tier: 47% recall at 50% precision |
| **Customer segmentation & next-best-offer**: +20% cross-sell conversion | K-Means behavioural segments, per-product propensity models trained point-in-time, and an offer ranker (propensity × margin) gated by credit pre-approval and the EWS watchlist | Contacting the top 20%: **+47% conversion** vs a "target the highest balances" rule, **3.1× random** (cards + loans, 1998 holdout) |

All numbers are regenerated by `python -m finsight.pipeline` into `artifacts/*.json`.

## Why this dataset

The **Berka / PKDD'99 Czech bank dataset** ([CTU Relational Repository](https://relational.fel.cvut.cz/dataset/Financial)) is a real bank's data: 4,500 accounts, 5,369 clients, **1.06M transactions**, 682 loans, 892 cards, standing orders and district economics. It was chosen because one coherent customer base supports all three problems:

- **Thin-file by construction.** There is no credit bureau. Applicants have a median of 13 months of banking history, and 10% have under 6 months. The only usable signal is behavioural and transactional, which is exactly the alternative-scoring setting.
- **Timed delinquency.** Overdrafts and penalty-interest charges date the start of distress for about 95% of loans the bank ultimately classed as bad. That makes a genuine time-to-event early-warning panel possible.
- **Dated product adoption.** Card issue dates, loan dates and insurance-payment start dates allow point-in-time propensity modelling.
- **Free and keyless.** The data is pulled from the repository's public read-only MariaDB, so no Kaggle account or API key is needed.

```

                                                     │
                     monthly account panel (185k account-months, dense, forward-filled)
                                                     │
            point-in-time window features (3/6/12m, strictly before the as-of month)
          ┌──────────────────────┬───────────────────┴────────┬────────────────────────┐
   credit scoring          early warning                segmentation            next-best-offer
   (at loan date)   ──PD──► (every loan-month)           (live snapshot)  ◄── propensity @ T0=1998-01
          │                       │                            │                       │
          └──── pre-approval ─────┴──── watchlist ─────────────┴─── eligibility gates ─┘
                                                     │
                     DuckDB warehouse (customer_360, loan_scores, ews_watchlist, offers …)
                              │                                   │
                      FastAPI decision API                Streamlit dashboard
```

```

  data/ingest.py            pull + clean the 8 source tables
```

## Quick start

```bash
python -m venv .venv && .venv/Scripts/activate      # Windows; use source .venv/bin/activate elsewhere
pip install -r requirements.txt
set PYTHONPATH=src                                   # export PYTHONPATH=src on macOS/Linux
python -m finsight.pipeline                          # ~4 min: download, features, 4 models, warehouse
streamlit run dashboard/app.py                       # http://localhost:8501
uvicorn finsight.api.main:app --app-dir src          # http://localhost:8000/docs
pytest -q
```

Or `docker compose up --build`.

Example API call:

```bash
curl -X POST localhost:8000/credit/score -H "Content-Type: application/json" \
     -d '{"account_id": 19, "amount": 120000, "duration": 36}'
```
It returns the PD, a 600-point-scale score, the decision band, and the top SHAP reason codes ("Lowest balance vs. instalment: reduces risk", …).

## Methodology notes (the parts reviewers ask about)

**Leakage control.** This dataset is notorious for leakage: the minimum balance after the loan date separates good and bad loans almost perfectly. Every feature here is computed from months *strictly before* the as-of month, and `tests/test_features.py` proves it by poisoning all future months and asserting the features don't change. The credit model is also checked out-of-time: trained on loans before Oct-1997, it scores AUC 0.969 on later ones.

**Credit scoring.**
- The baseline is a logistic regression on what a lender without transaction data would see: loan amount, duration, instalment, age, gender and district economics.
- The behavioural models add balance levels and minimums, instalment coverage (lowest balance ÷ instalment), payment-to-income, income volatility, cash share of spend, activity, and momentum.
- PD is mapped to a scorecard scale: 600 points at 50:1 odds, 20 points to double the odds.
- The NPA claim compares the bad rate of the approved book at the *same* approval rate, which is how a credit committee would compare policies.
- Thin-file (<6 months history) AUC is 0.865.

**Early warning.**
- Delinquency onset = the first overdraft or penalty-interest charge after disbursement.
- Each running loan is observed monthly until onset. The label is "onset in the window 30–90 days from now", so an alert always leaves at least a month to intervene.
- Instalment-stress features: months where the lowest balance fell below the instalment, last-month minimum balance ÷ instalment, and the slope of the minimum balance. The origination PD from the credit model is also a feature.
- Precision is measured **per borrower**: a flag counts as correct only if delinquency follows ≥30 days later.
- Thresholds are tuned on out-of-fold scores over 45 delinquent borrowers, so treat ±10pp as the realistic band.

**Segmentation & NBO.**
- 10 behavioural features, K-Means, with k picked by silhouette (k=4, 0.29). Segment names are generated from each centroid's most distinctive features.
- Propensity models train on features as of 1998-01-01 and label adoption during 1998, using only customers who didn't hold the product.
- **Tenure is deliberately excluded.** In this bank, standing-order products such as insurance start about 5 months after account opening, so tenure would learn the onboarding clock instead of genuine propensity.
- Insurance has only 22 adopters in the window, so it is offered but excluded from the headline uplift.
- Offers are ranked by propensity × illustrative margin. Credit products are only offered to customers who pass a standard pre-approval (120k CZK / 36 months, auto-approve band) and are not on the EWS watchlist.

## Limitations & next steps

- The data is from 1993–98 and small for credit (682 loans, 76 bad), so CV variance is real. Bootstrap confidence intervals would be the next addition.
- There is no savings product in the source data. The cross-sell targets are cards and loans, with insurance as a low-data product.
- Product margins are placeholders to be replaced with finance-supplied values.
- Production hardening would add an MLflow model registry, PSI drift monitoring on the monthly panel, a fairness review of protected attributes (`is_male`, age), which are currently model inputs, and a real champion/challenger A/B test for NBO.
